# Socrates implementation contracts

These contracts define the proposed first vertical slice. The [architecture](architecture.md#component-inventory-and-extension-review) maps responsibilities and test evidence to C1–C8. The [PRD](prd.md#requirements-and-acceptance) defines the observable experience. Finalize the shared fixture and schema together before implementation.

## Session API and event contract

Use same-origin JSON over HTTPS and an authenticated Server-Sent Events stream. Use one `v1` contract shared by the Next.js client and FastAPI. The fixture contains synthetic data only.

| Request | Role | Contract |
| --- | --- | --- |
| `POST /api/v1/sessions` | Student | Start a lesson from a curated `lessonId`; return `sessionId`, `task`, `boardRevision`, and latest `seq`. One active lesson per station. |
| `PATCH /api/v1/sessions/{id}/board` | Paired student device | Start or finish an edit against an expected board revision. Starting an edit advances the revision and invalidates pending plans and candidates. Editing remains local until the student submits the row. |
| `POST /api/v1/sessions/{id}/heartbeat` | Paired student device or operator | Renew a short lease for the caller's device and role. Include the current board revision for the student device. Expired leases keep the executor parked or trigger its local stop. A heartbeat never arms or approves the robot. |
| `POST /api/v1/sessions/{id}/submissions` | Student | Submit `submissionId`, `task`, `rowId`, `rowRevision`, `boardRevision`, and exactly one input mode. Use JSON for ink or text and bounded multipart for audio. Return a candidate or a typed unsupported/busy error. Submit again with a fresh ID after editing the row. |
| `POST /api/v1/sessions/{id}/submissions/{sid}/confirm` | Student | Confirm or correct the bounded `text` at the same revision. Atomically persist the grade and advance the lesson if eligible. Return the verdict and current `seq`. |
| `GET /api/v1/sessions/{id}` and `GET /api/v1/sessions/{id}/events` | Student or paired operator, role-filtered | Read the current snapshot or subscribe with `Last-Event-ID`. Replay bounded events by `seq`, or signal `resync` so the client reloads the snapshot. A browser connection never arms the robot. |
| `POST /api/v1/sessions/{id}/hints` | Student | Request a follow-up hint for the current graded attempt. Deduplicate by request ID and record assistance before returning a hint. |
| `POST /api/v1/sessions/{id}/finish` | Student | Close an incomplete lesson on request. A correct transfer closes a complete lesson. Both paths commit a summary atomically. |
| `POST /api/v1/plans/{id}/displayed` and `/approve` | Paired student device for display; operator for approval | Bind display and approval to exact plan version/digest and board revision. Approval requires preview eligibility and a cleared work area. |
| `POST /api/v1/robot/stop` | Paired operator or current student | Request an idempotent software stop. Physical stop and local re-arm work independently of the app. |
| `GET /api/v1/sessions/{id}/summary` | Paired caregiver | Return one scoped summary and no raw media. The student may see their own session result in the board. |

Events carry `v`, `sessionId`, `seq`, `type`, `boardRevision`, optional `rowId`/`rowRevision`, and typed `data`. Minimum types are `candidate.ready`, `attempt.checked`, `hint.ready`, `plan.preview`, `plan.state`, `skill.updated`, and `session.finished`. Emit a sequence only after its durable transaction commits. Clients ignore older revisions and already applied sequence numbers. A deliberate new edit invalidates a pending candidate or plan. API errors include a stable code, recoverability, and current revision when applicable. Same idempotency key and payload returns the recorded result; key reuse with different content or stale revisions yields `409`. Duplicate confirms may return a prior result but cannot schedule a second motion or skill update.

Session tasks progress `seed → factor → roots → transfer → finished`. A wrong attempt stays in its current task. A transfer submission contains both a factorization and the full root set. A correct first transfer earns independent evidence only if the learner did not request help. Later correct attempts earn practice evidence. Preserve the last accepted work and mark a stale attempt as superseded in the view. On reconnect recover the committed lesson and retain any unsent local draft. Retire pending physical plans and require a fresh preview and approval.

## Board capture, maths, and hints

- **C1/C4 capture:** use a fixed-aspect board coordinate system with origin at the top left and normalized `[0,1]` coordinates. Letterbox it within each viewport. Preserve `strokeId`, points `{u,v,tMs,pressure?}`, and the active row. Handle pointer cancellation and coalesced events when supported. The board retains the draft until submit. The server rasterizes the single row with a stroke-to-crop transform. Capture bounded push-to-talk audio, transcode supported iPad formats to the speech service input, and stop capture when the user releases or leaves the view. No background recording.
- **C4 recognition:** return `Candidate {source, text, uncertainty?, tokenSpans?}`. A span maps a normalized token to verified stroke IDs or a board-space box. Treat model confidence as advisory. Require explicit confirmation of all handwriting and voice candidates. If edited text invalidates span alignment, mark the entire row. Vision and ASR never grade or choose a motion path. Keep typed entry for both. Initially cap text at 256 characters, ink at 64 strokes and 4,096 total points per row, generated raster at 1024 px on its long edge, and audio at 15 s/2 MiB. Reject inputs exceeding the configured limits with a recoverable response.
- **C3 parser and checker:** allow ASCII/Unicode minus and superscript two, integers with bounded magnitude, `x`, addition/subtraction, parentheses, implicit multiplication for in-scope factors, `^2`/`²`, an equation equals sign, and separators for root lists. Use a bounded lexer and grammar with typed AST constructors, never `eval`, `sympify` on raw input, or `parse_expr` on untrusted input. Limit depth, terms and coefficients before constructing SymPy objects. Normalize equations by subtracting RHS from LHS. For factors require two monic linear factors with RHS zero, compare expanded coefficients and compute sum/product evidence. Compare the full set of normalized integer roots for the roots task. Canonicalize order and duplicates. An unsupported transformation receives a format prompt. Guard runtime on malformed and adversarial input.
- **C3 result:** `CheckResult {verdict, reasonCode, evidence, tokenRefs, task, rowRevision}`. `verdict` is `correct`, `incorrect`, `unsupported`, or `needs_confirmation`. Reason codes include `WRONG_SUM`, `WRONG_PRODUCT`, `WRONG_SUM_AND_PRODUCT`, `ROOT_SET_MISMATCH`, `UNSUPPORTED_FORM`, and `AMBIGUOUS_INPUT`. Only verified `incorrect` produces Mistake Glow and a mathematical hint. A deterministic formatter turns the reason code and facts into the visible explanation. For the demo bad factors, `observedSum=-5`, `expectedSum=5`, `observedProduct=6`, `expectedProduct=6`.
- **C5 question:** accept only the checked task, reason code, bounded numeric evidence, and hint depth. Keep raw user and model-generated text out of privileged instructions. Select a prompt target from the lesson's allowed targets (e.g. compare the sign of the original middle coefficient). Require one bounded question (≤140 characters), no executable content, and no disclosure of a correct factorization or root set. Use NeMo Guardrails where qualified, and use application validation plus a vetted template whenever safety, grounding, or timing is uncertain. `WRONG_SUM` example: “What sign does the middle term in your original equation have?” The audio adapter receives exactly the displayed question. Show text immediately and make audio optional. TTS failure never hides the question.
- **C1 feedback:** use the verified box when available, an underline and “Check this step” label, and a compact reason. Keep student ink, mistake overlay, and Ghost Ink on separate layers. Keyboard and screen-reader users can enter the same maths and read the same feedback. Typed fixes and undo must visibly invalidate any old preview.

## Robot execution and calibration

**C7 plan.** The app requests a typed `circleRegion` or `drawGlyphs` intent with a row revision, an approved local glyph set and explicit placement. The planner creates `StrokePlan {planId, version, digest, sessionId, boardRevision, rowRevision, calibrationId, mode, expiresAt, paths}`. `paths` are normalized, ordered pen-up/pen-down segments with bounded point counts, pen-up travel and safe clearance. Validate finite coordinates, segment length, speed, acceleration, joint range, workspace, clearance, continuity, and reachability for the entire plan. Reject without movement if any segment fails. Ghost Ink and the executor consume the same approved geometry, with the executor using the pinned calibration profile. An alternate path after preflight needs a new plan and preview. Use a registered copy of the demo row for the matching circle on paper; arbitrary digital student ink has no physical paper counterpart.

**C7 lifecycle.** `parked → previewed → approved → running → complete` for one job at a time. `cancelled` and `faulted` are terminal for that job. Hold Ghost Ink for at least 500 ms after paired-display acknowledgement and require operator approval, valid heartbeat, fresh calibration, no active edit and a clear workspace. While a plan is approved or running, the board disables pen, typing, and undo controls and keeps Stop available. A revision update or lease expiry invalidates motion eligibility. The process owning the serial link checks locally before any command and enforces the watchdog during movement. It does not auto-retry a partially executed path or continue after process restart, fault, lost heartbeat, or emergency stop. A separate hardware stop cuts actuator power. Define a fixture-specific safe stop with the operator and verify stopping distance/latency before screen contact. Fault recovery requires a local inspection, fresh calibration if needed, re-arm and a fresh plan. Keep physical arming disabled by default.

**C8 calibration.** Use a fixed arm and a marked rectangular surface. Store `CalibrationProfile {id, fixtureId, surfaceMode, cornersMm, toolOffsetMm, safeZMm, contactZMm, workspaceLimits, verifiedAt}`. Define `u,v` on the board, map to plane millimetres, then apply tool offset and validated inverse kinematics. Verify independent interior points in addition to corners. Reject a moved/rotated fixture, invalid geometry, stale profile, changed tool, or unreachable point. A profile for paper cannot authorize contact with glass. Prefer a squared frame and inspect error before enabling any warp correction. Build the offline replay from plan samples; it supplies evidence for clearance, never authorization.

| Ladder rung | Evidence before progressing |
| --- | --- |
| Corners | Dry run, confirm workspace and hard stop, then validate calibration with a separate interior grid. Proposed paper gate: p95 error ≤2 mm and max ≤3 mm over ≥20 measured locations. |
| Line → circle → square | Three dry runs then ≥5 supervised paper repeats per shape. Check closed outlines and endpoints against the same error limits, and confirm zero out-of-bounds moves and no unexpected contact. |
| Digits → equation | ≥5 readable repeats of `0–9` and the seed equation at the intended size on paper. Compare trace to the preview and exercise stop, serial loss, missed heartbeat, stale approval and duplicate request. |
| iPad contact | Verify Pencil/iPad compatibility, a rigid fixture, a compliant tool mount and safe contact force/height on a sacrificial protected surface. Re-run the geometry and stop tests with signed operator sign-off and documented limits before a supervised iPad session. Until a contact force and stopping-distance limit are measured and agreed, do not enable screen mode. |

## Evidence, storage, and access

- C6 stores pseudonymous session IDs, task attempts, reason codes, structured evidence, assistance flag and resulting skill evidence. Derive summary and skill state from committed attempts. Store `not_yet`, `practiced_with_help`, and `checked_independently` with references to the attempts that earned each state. For MVP show current-session evidence and a next-step suggestion, with no cross-learner ranking.
- Store ephemeral row ink/audio only as needed to render or recognize the active lesson. Dispose of audio and recognition rasters after processing, and clear drafts after close unless needed during a short reconnect. Keep demo evidence on the Spark and provide an operator deletion path for a session and its summary. Set and verify retention and consent before a real learner pilot.
- Keep student, caregiver and operator authorization checks server side on every protected request and stream. Default to local LAN access and approved model endpoints. Check audio payload size, mathematical resource bounds, plan budgets and GPU queue length. Version the stored schema, event contract and calibration profiles independently. For compatibility changes, add new fields with defaults or version the contract and replay the old fixture.
