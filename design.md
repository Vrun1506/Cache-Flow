# Socrates implementation contracts

**Status:** target v2 contracts. [final-plan.md](final-plan.md) is the build handoff and [Interface.md](Interface.md) owns the migration from the committed Swift client. These contracts are not implemented by the current mock. Keep actual code and these documents synchronized in a future change.

## Domain contracts

Recognition returns Candidate {text, regions, ambiguity, source_revision, model_revision}. If an uncertain sign, exponent or symbol affects a verdict, require student confirmation. The candidate is never silently treated as ground truth.

A subject verifier accepts {subject, original_problem, prior_step?, candidate_step, step_kind, domain_assumptions, board_revision, budget} and returns Evidence {verdict: valid|invalid|partial|unknown, reason_code, normalized_step, proof_or_counterexample?, first_error_region?, evidence_id, source_ids[], board_revision, verifier_version}. Use the repository's pinned Pydantic v2 for Python schemas and shared Swift JSON fixtures. The algebra strategy tokenizes a **small whitelist grammar**, constructs SymPy objects from its parse tree, and runs bounded symbolic operations in a restricted worker. It never sends untrusted text to `parse_expr`, which [uses `eval`](https://docs.sympy.org/latest/modules/parsing.html). `equivalent_equation` compares solution sets under assumptions; `factorization` proves an identity; `candidate_root` substitutes into the original equation and may return `partial_root`; `solution_set` checks validity and completeness. Numeric sampling may disprove but not prove equivalence. Malformed/unsupported/time-limited input is `unknown`, not correct.

A Socratic turn accepts {learner_intent, confirmed_question, confirmed_work, evidence, assistance_history, skill_map, retrieved_sources?} and returns exactly one move {ask|hint|explain|write_step|draw|show_answer|clarify|recap}, caption, matching spoken text, optional highlight, tutor-ink or scene intent and cited evidence IDs. A correctness statement must cite a current valid/partial verifier result. A subject without a verifier can discuss evidence but must say when it cannot grade. Tutor text, speech, ink and scenes pass the same answer-leakage policy. `show_answer` requires explicit intent or the recorded repeated-struggle rule and marks the item assisted; a fresh check is needed for independent credit.

## Agent and tool boundary

NemoClaw runs one tutor agent with a versioned, attributed adaptation of the [MIT-licensed Jane Street skill](https://github.com/janestreet/agent_skills/blob/master/LICENSE.md) against one Spark-local vLLM endpoint. Confirm both skill discovery and actual activation in a new session. OpenShell allows only local inference plus a local, authenticated Streamable HTTP MCP math service, subject to the Phase 0 bridge proof. Expose narrow tools such as `check_math_step` and optional `retrieve_source`; each has bounded JSON arguments, no filesystem paths, and a response with explicit reason/evidence. The agent does not get generic shell, code execution, unrestricted browsing, or direct database writes. The lesson service owns session state and verifies every returned tool result before committing a tutor turn. The model proposes the tool call; gateway-side verification is logged separately.

NeMo Guardrails applies input, tool-call, tool-result and output checks. Pin the engine and use a startup assertion that required tool rails actually loaded; [NVIDIA warns that incompatible IORails configuration can fall back without tool rails](https://docs.nvidia.com/nemo/guardrails/configure-guardrails/guardrail-catalog/tool-calling). A failed rail, invalid result or unavailable verifier yields a clarification or “cannot check this yet” response. It cannot produce a confident correctness claim.

The first integration spike must prove that the NemoClaw agent can receive a request from the local session service, load the skill, call the math MCP service, and return a structured turn within a measured latency budget. If the bridge fails, report NemoClaw as unintegrated and resolve it before claiming the required demo; never label a direct Python call as a harness call. Ollama and NAT do not sit in this critical path.

## Digital ink

Tutor writing is a semantic intent {text_or_formula, placement_region, style, source_turn_id} plus a validated board-space preview. A scene intent contains approved primitives such as labelled shape, arrow, number line or bounded plot; it never contains executable code. The iPad commits a separate tutor layer after placement acknowledgement and a matching {session_id, board_revision, turn_id} check; it must not synthesize a fake physical-arm event. Bound points, strokes, glyphs, coordinates, scene complexity and animation duration. Preserve the student's Pencil drawing and undo history. If the board changed while the tutor was composing, discard the stale preview and re-evaluate. Speech, caption, ink and scene share the turn ID so cancellation stops all four.

The current Swift app has arm-named Step/ArmJob events, any-input tutor phases and fallback ghost ink. Those are v1 compatibility surfaces, not the target implementation. Refactor them together with the mock, tests and [Interface.md](Interface.md). In particular, keep Pencil-only student capture while programmatically rendering tutor ink; do not switch the student's touches to tutor ownership.

## Speech

Current iOS records full 16 kHz mono WAV push-to-talk and plays a clip URL with on-device speech fallback. Preserve that local input and fallback path. One spoken learner turn is required in the demo: the proposed ASR adapter is the Spark-supported Parakeet 1.1B CTC English NIM, with Omni audio input as a documented local substitute if co-residency or quality fails. Transcription is confirmed when ambiguous. Push-to-talk is not full duplex. Local Magpie TTS output and immediate matching captions are first-demo requirements, subject to a co-residency test and a documented local equivalent if Magpie cannot run. Do not save microphone WAV beyond the active request. Cancellation invalidates queued clips, ink and scenes for the superseded turn.

## Knowledge ingestion

A teacher/operator imports approved pages locally. Parse/OCR runs only through a proven local adapter; attach source title, page, version and rights metadata. Chunk the text, compute local embeddings, optionally rerank locally, and return short cited passages with retrieval scores. Retrieved text is untrusted input and cannot issue agent commands. The tutor cites the source and states uncertainty when evidence is missing. Nemotron Parse is deferred on Spark until a supported local deployment is established.

## Lifecycle and verification

One session has monotonically increasing board and turn revisions. Requests include idempotency IDs; duplicate Check calls cannot duplicate an attempt or tutor ink. Reconnect replays problem, phase, latest board/turn and evidence summary, without replaying audio. Require session-scoped student/operator permissions; admin routes are authenticated, even on LAN. Keep audio and images ephemeral, store only consented minimal evidence, and offer deletion. Run: Swift package tests and simulator build; FastAPI contract and math suites; rail and sandbox deny fixtures; local model/speech smoke; a real offline iPad–Spark rehearsal. All are pending for v2.
